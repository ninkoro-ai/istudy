# 我ai学习 · 产品需求文档（重构版 · 功能设计）

> 版本：v1.0（重构版）　日期：2026-08-08
> 性质：**功能设计文档**。本文只定义产品“做什么、怎么运作、按什么规则”，不涉及界面布局、视觉风格、交互细节；界面设计以本文为输入另行产出。

## 1. 产品概述

### 1.1 产品定位

面向「2026 考研专硕 095131 农艺与种业（作物方向）」考生的**本地优先备考工作台**：把 90 天备考周期拆成可执行、可追踪、可复习的学习计划，覆盖四门科目（政治、英语二、339 农业知识综合一、881 作物栽培育种与种子科学）。

### 1.2 产品原则

1. **本地优先**：核心功能完全离线可用，学习数据默认只存在设备本地，不上传任何服务器。
2. **可执行**：每天打开就知道“今天学什么、还剩什么、错在哪、何时复习”。
3. **可自适应**：计划与复习节奏随真实掌握情况动态调整，而非一成不变。
4. **可验证**：学习结果由测评与数据支撑，用户能看见自己的进步曲线。
5. **可扩展**：内容体系与规则参数化，考纲变化、内容扩充不需要改产品逻辑。

### 1.3 产品目标与成功指标

| 目标 | 衡量指标 |
|---|---|
| 学习连续性 | 计划期内“完成日/计划日”≥ 80% |
| 知识覆盖 | 计划结束前知识点掌握率 ≥ 90% |
| 复习有效性 | 到期复习完成率 ≥ 85%；错题二次重练正确率 ≥ 75% |
| 留存 | 连续 7 天使用率 ≥ 60%（统计周期内） |

### 1.4 目标用户与核心场景

- **在职/在校考生**：碎片时间学习，需要“打开即学、离线可用、随时可停下”。
- **换设备场景**：备份导出/导入即可迁移，数据不丢。
- **冲刺复盘场景**：需要清晰的错题收敛与掌握度趋势，知道薄弱科目与章节。

## 3. 功能需求详述

> 每条需求以 `FR-编号` 标识；`BR-编号` 为业务规则；`AC-编号` 为验收标准。

### 3.1 F1 学习计划引擎

**目标**：把备考周期拆成每日任务，随进度自适应。

- FR-1.1 计划以“天数”为单位（默认 90 天，参数可配置），每天由“新学任务 + 到期复习任务”组成。
- FR-1.2 四门科目按权重顺序铺开：计划期前段完成全部知识点的首轮覆盖，后段以复习与综合为主。
- FR-1.3 每日新学数量有上限（默认 4–8 个/天，可配置），防止一天任务过载。
- FR-1.4 计划支持“轻量日”机制（如月假/轻松日）：当天仅保留部分科目任务，其余免除，且不破坏连续打卡。
- FR-1.5 计划可整体延后/提前（休假场景），延后不删除已完成记录。
- FR-1.6 阶段划分（基础/强化/冲刺）由计划天数比例推导，阶段影响每日任务构成（如冲刺期以复习与套题为主）。

- BR-1.1 计划起点为用户首次启用日；已有存档迁移时保留原起点。
- BR-1.2 已完成的知识点不会因计划调整而重新出现在“新学”任务中。

- AC-1.1 任意一天都能明确回答：今日新学 N 个、待复习 M 个、已完成 X 个。
- AC-1.2 轻量日生效后当天任务科目数减少，且连续打卡不被中断。

### 3.2 F2 知识点内容体系

**目标**：内容与逻辑解耦，支持扩充与更新。

- FR-2.1 知识点为最小学习单元，包含：标识、标题、正文、出处/章节、科目、可选难度、可选标签、可选关联知识点。
- FR-2.2 知识点按“科目 → 章节 → 知识点”组织，章节可折叠聚合统计。
- FR-2.3 每个知识点至少绑定一种测评能力：单选、多选、判断、填空、术语匹配（至少其一）；不满足时允许“阅读模式”。
- FR-2.4 内容以数据包形式管理（版本号 + 内容清单），支持整体替换/增量更新，更新不破坏学习进度（按知识点标识匹配）。
- FR-2.5 内容包可在构建期校验完整性（标识唯一、引用有效、测评项完整、覆盖统计），校验失败不得发布。

- AC-2.1 内容包校验能发现：标识重复、引用不存在、测评项缺失、章节统计不一致。
- AC-2.2 更新内容包后，已学知识点的掌握状态保持不变。

### 3.3 F3 学习与掌握

**目标**：明确每个知识点的学习状态与掌握度，作为复习与统计的依据。

- FR-3.1 知识点状态机：`未学 → 学习中 → 待复习 → 已掌握`；任意状态可因“答错/重学”回到前序状态。
- FR-3.2 掌握度 0–100，由以下因素综合：复习轮次、近期正确率、距上次学习天数、错题数量；各因素权重可配置。
- FR-3.3 “学习中”指已进入测评但尚未达到掌握标准；“待复习”指到期的已掌握知识点。
- FR-3.4 学习动作（完成新学/复习/重练）必须产生状态变更或记录，不允许“空操作即掌握”。
- FR-3.5 支持“阅读模式”：无测评能力的知识点，用户主动确认“已读完”后才记为已学，并计入掌握流程。

- BR-3.1 掌握度下限 0、上限 100，任何计算都必须收敛到该区间。
- BR-3.2 取消掌握（主动重置）会扣减对应奖励并恢复“未学/学习中”状态。

- AC-3.1 连续答错或长期未复习的知识点，掌握度随时间下降；复习成功后回升。

### 3.4 F4 测评系统

**目标**：以测评驱动学习，覆盖考纲题型，产出可靠错题数据。

- FR-4.1 支持题型：单选、多选、判断、填空、术语匹配；问答/简答以“自评”方式提供参考答案，不自动判分。
- FR-4.2 一场测评由 3–7 题组成，可配置限时（默认 5 分钟）；超时自动交卷。
- FR-4.3 通过线：题目数 ≤3 时全对，>3 时允许错 1 题（可配置）。
- FR-4.4 测评机会：每个知识点每次“掌握判定”最多 2 次；第 2 次仍未通过则视为本次未掌握，且需间隔冷却后才能再次挑战。
- FR-4.5 每道错题记录：知识点、题目、所选答案、正确答案、时间；同一错题去重展示但保留次数。
- FR-4.6 测评结果必须展示逐题正误与解析，并写入正确率统计。
- FR-4.7 自动出题：内容无手写题时，按规则由知识点正文生成可用题型（保证选项可区分、有唯一答案）；生成质量纳入校验。

- BR-4.1 任何测评必须防重复提交（一次提交只结算一次）。
- BR-4.2 已掌握知识点重复测评通过时，不再重复发放掌握奖励，但更新正确率统计。

- AC-4.1 错题本中的每一条都可追溯到原始题目与解析。
- AC-4.2 自动生成题不含歧义选项，答案唯一。

### 3.5 F5 复习引擎

**目标**：按遗忘曲线安排复习，随表现自适应。

- FR-5.1 复习间隔表可配置（默认 [1,3,7,15,30] 天），每个知识点独立维护“复习步”。
- FR-5.2 自适应规则：近期正确率高 → 间隔拉长或跳步；正确率低 → 间隔缩短或原地巩固；规则阈值可配置。
- FR-5.3 排期基线 = “上次复习成功日”（优于“最近学习日”），确保间隔真实反映遗忘进程。
- FR-5.4 到期复习清单每天自动生成，复习完成即记录并推进复习步。
- FR-5.5 错题重练按错误次数排期（默认 [1,3,7] 天），到期提示重练；重练通过后从错题本移除该知识点记录。
- FR-5.6 复习步达到上限后视为“长期掌握”，不再自动排期。

- AC-5.1 给定同一知识点，正确率不同则下次复习间隔不同（可测）。
- AC-5.2 复习成功日与最近学习日不同时，排期以复习成功日为准（可测）。

### 3.6 F6 打卡与激励

**目标**：维持学习连续性，提供正向反馈，同时防作弊。

- FR-6.1 当日全部应完成任务满足后自动“完成打卡”，记录当日完成时间。
- FR-6.2 连胜 = 从今天起向前连续的已打卡天数（含今天）。
- FR-6.3 缺卡日支持补卡：须补做当日任务后，以“补卡”形式记满，奖励为正常的一半；每日最多补一次。
- FR-6.4 积分体系：掌握知识点、完成打卡、连续全勤里程碑、错题清零等均可获得积分；规则可配置。
- FR-6.5 成就/奖励：积分可兑换奖励（含“轻量日”）；连续打卡有里程碑成就。
- FR-6.6 防作弊：取消掌握扣分、恶意打卡（多轮不过仍强行通过）扣分、积分下限 0；禁止任何绕过测评的“直接掌握”路径（阅读模式除外，但需显式确认）。

- BR-6.1 同日重复满足条件不重复发奖。
- BR-6.2 空任务日不判满、不打卡，避免误发。

- AC-6.1 连胜 7/14/21/30 天时各触发一次里程碑奖励，且不重复。
- AC-6.2 补卡只对“过去、计划内、未满”的日期开放，且补后标记为“补”。

### 3.7 F7 数据与统计

**目标**：让用户看见进度与问题。

- FR-7.1 每日学习快照：当天完成数、待办数、复习数。
- FR-7.2 长期报告：掌握度趋势、打卡热力、科目掌握分布、错题收敛曲线、预计完成度。
- FR-7.3 所有统计由本地数据实时计算，不得依赖外部服务。
- FR-7.4 统计口径在文档中固定（见 §5），保证跨版本可比。

- AC-7.1 统计数值与明细记录一致（可抽查）。

### 3.8 F8 学习辅助

**目标**：提升单点学习效率。

- FR-8.1 全库搜索：按标题/正文/出处/错题检索，结果高亮且可直达知识点。
- FR-8.2 每日备注：按日期记录目标、安排、自语；备注不参与任何评分。
- FR-8.3 AI 讲题：为知识点生成结构化讲解提示词（角色、框架、可视化建议、类比、考法、互动练习、复习卡），支持“复制到外部 AI”与“使用用户自带 Key 直接请求”两种方式；AI 调用不得上传学习数据（除用户主动提交的当前知识点内容）。
- FR-8.4 提示词脚本：用户可保存/复用自定义讲题脚本。

- AC-8.1 搜索空查询不报错；超长查询不导致卡死。
- AC-8.2 AI 请求失败时，原“复制提示词”路径始终可用。

### 3.9 F9 数据管理

**目标**：数据不丢、可迁移、可恢复。

- FR-9.1 本地主存储采用结构化存储（IndexedDB），支持大容量与事务；另保留轻量镜像用于快速启动。
- FR-9.2 备份导出：明文 JSON 与口令加密（AES-256-GCM + 口令派生密钥）两种格式；文件含版本号与完整状态。
- FR-9.3 导入：校验格式与版本，导入前自动备份当前数据；畸形数据拒绝导入并说明原因。
- FR-9.4 清空：二次确认后清空全部本地数据，且同时清除各存储介质，防止“清空后被镜像自动恢复”。
- FR-9.5 数据迁移：导出文件跨设备/跨版本可导入，缺失字段按默认值补齐。
- FR-9.6 （二期）可选云同步：以“用户自持口令加密”为前提，服务端不可读明文。

- AC-9.1 导出→清空→导入后，进度/错题/积分与导出时一致。
- AC-9.2 旧版本备份导入不崩溃，缺失字段安全兜底。

### 3.10 F10 通知与提醒

**目标**：在合适的时机提醒用户。

- FR-10.1 到期复习提醒（每日一次，可关闭）。
- FR-10.2 新版本可用提示（一键刷新）。
- FR-10.3 提醒全部本地生成，不依赖推送服务；离线时降级为应用内提示。

## 4. 核心业务规则汇总

### 4.1 知识点状态机

```
未学 ──(通过测评/确认阅读)──▶ 学习中/已掌握
学习中 ──(通过测评)──▶ 已掌握
已掌握 ──(到达复习日)──▶ 待复习
待复习 ──(复习通过)──▶ 已掌握（复习步+1）
任意 ──(取消掌握/答错重置)──▶ 前序状态
```

### 4.2 掌握度模型（可配置参数）

```
基础分 60
+ 复习轮次 × 8（封顶 5 轮）
− 错题数 × 4（封顶 5 条）
− 距上次学习天数 × 0.6（封顶 30 天）
+ 正确率加成（高于 70% 加分，低于则减分）
→ 收敛到 [0,100]
```

### 4.3 复习排期（可配置）

```
间隔表默认 [1,3,7,15,30]
基线 = lastReview || lastStudy || 计划起点
自适应：
  正确率 ≥ 90% → 间隔 ×1.5，复习步 +2
  正确率 < 60% → 间隔 ×0.6（≥1 天），复习步 +0
复习步 ≥ 上限 → 长期掌握，不再排期
```

### 4.4 积分规则（可配置）

| 行为 | 分值 |
|---|---|
| 掌握一个知识点 | +10 |
| 当日打卡完成 | +20（连胜 ≥3 天 ×1.5 = 30） |
| 连续全勤 7/14/21/30 天 | +30 / +50 / +80 / +120（每档一次） |
| 错题全部清零 | +30 |
| 取消掌握 / 恶意打卡 | −10 / −20（下限 0） |

## 5. 数据需求（实体与字段，不含界面）

| AI 配置 | BaseURL、模型、Key（仅本地） | 不进备份 |

## 6. 非功能需求

### 6.1 性能
- 冷启动到可交互 ≤ 2s（主流中端手机，本地数据 <5MB 场景）。
- 列表渲染百级条目无明显卡顿；搜索 1000 条内 ≤ 100ms。
- 离线优先：所有核心功能断网可用。

### 6.2 隐私与安全
- 学习数据默认不离开设备；AI 调用仅发送用户主动触发的内容。
- 备份加密口令不落盘、不随备份存储。
- 导入数据强校验，拒绝畸形值注入。

### 6.3 兼容性
- 现代移动浏览器（iOS Safari、Android Chrome/微信 WebView）与桌面浏览器。
- 移动优先，适配不同屏幕尺寸与安全区；支持安装为 PWA。

### 6.4 可访问性
- 键盘可操作、焦点可见；弹层具备语义标注；尊重系统“减弱动态效果”。

### 6.5 可维护性与可测试性
- 业务规则（状态机、排期、积分、掌握度）必须为纯函数，可单元测试。
- 数据校验在构建期执行；核心链路有自动化冒烟测试。
- 全部文案集中管理，可独立维护。

### 6.6 数据可靠性
- 关键写入具备容错；存储不可用时降级提示且不崩溃。
- 备份/恢复流程必须有自动化验收用例。

## 7. 里程碑规划

| 里程碑 | 内容 | 出口条件 |
|---|---|---|

## 8. 验收总则

1. 每个 P0 功能均有可执行的验收用例（AC）。
2. 断网状态下 P0 功能完整可用。
3. 业务规则（§4）可被自动化测试覆盖，改规则不改核心结构。
4. 无任何“空操作即完成”路径；所有学习动作都有记录。

---

## 9. 明确不包含（本版范围外）

- 界面布局、视觉风格、交互动效、品牌视觉（另行设计文档）。
- 社交/排行榜等多人功能。
- 官方题库版权内容制作（内容包由运营侧按考纲产出，本 PRD 只定义内容模型与校验）。
- 服务端账号体系（除非二期云同步引入，且默认关闭）。

---

## 10. 开放问题（需产品决策）

1. 计划默认时长：固定 90 天，还是首次使用时用户可选 60/90/120 天？
2. 每日新学上限是否允许用户手动增减（影响计划密度）？
3. AI 讲题默认形态：仅提示词导出，还是引导用户配置自带 Key 直接对话？
4. 云同步是否纳入正式路线图（涉及隐私与成本）？
5. 学习时长记录（番茄钟/会话计时）是否作为 P1 功能？
