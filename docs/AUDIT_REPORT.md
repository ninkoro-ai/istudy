## 三、缺陷清单（已全部修复）

| # | 严重度 | 缺陷 | 影响 | 修复 |
|---|---|---|---|---|
| D1 | 高 | `init()` 每次启动无条件把 `S.startDay` 重置为 `2026-08-02` | 导入的自定义起点、清空后“从当天重开”都会在下次打开时失效；与 PRD §7.1/§7.8 矛盾 | 仅当缺失或非法日期时使用默认值 |
| D2 | 高 | `sanitizeImport` 未处理 `prepShown`；导出缺少 `attempts / wrong / prepTriggered / prepShown` | 备份/恢复有损：错题、答题机会、引导状态会丢失 | 导入补齐 `prepShown`，导出与导入前备份均改为全量字段 |
| D3 | 高 | 冲刺期“复习任务”点进闯关后按新学处理（`recordLearn`），`reviewed` 标记永不写入 | 第 91 天起复习任务永远无法满足，当日无法打卡，进度卡死 | `toggleKp` 检测今日任务模式，复习任务自动以 review 模式进入闯关 |
| D4 | 中 | 无可用题目的知识点在 `openQuiz` 中被**静默自动掌握并 +10 分**（零交互） | 违背闯关/防作弊设计；用户未阅读即“掌握” | 新增“纯阅读模式”弹窗：展示正文，点击“我已认真读完，标记掌握”后才加分 |
| D5 | 中 | 答题结算无防重复提交保护 | 计时归零与手动提交同时触发时可能重复发分 | `sq()` 增加 `submitted` 一次性标记 |
| D6 | 低 | 清空数据未重置 `prepDate / prepTriggered / prepShown` | 清空后当日引导弹窗不再出现（残留旧日期） | 清空时一并重置 |
| D7 | 低 | `COVER_DAYS` 固定 90，`studyDays` 可被导入为 30–365 | 自定义计划长度时知识点铺开天数与实际计划错位 | `init()` 中 `COVER_DAYS = TOTAL` |
| D8 | 低 | 剪贴板复制无兜底 | `file://` 或非安全上下文下复制失败无提示 | 增加 `execCommand` 降级与失败提示 |
| D9 | 低 | 营销页写“90 天，从打开这一刻算起”，与实现（8 月 2 日开跑）不一致 | 用户认知偏差 | 文案改为“90 天，从 8 月 2 日开跑” |

## 四、PRD 与实现偏差记录（已随 PRD 副本修正）

1. §7.1「缺失 startDay → `dateStr(0)`」：实现为**默认 `2026-08-02`**（考研周期起点），且原先会被 `init()` 无条件覆盖（D1）。PRD 已改为“缺失 → 2026-08-02”。
2. §3 常量表列有 `PERIOD_MAX=2`：原代码**并无该常量**（硬编码 2）。已新增常量并统一引用。
3. §13「导出字段不含 attempts/wrong/prepTriggered/prepShown」：已改为全量导出（schema 仍为 v2，向后兼容）。
4. §12.2「无题可出 → 退化为纯阅读」：原实现其实是**静默自动掌握**，现已改为显式确认的纯阅读模式，与 PRD 描述对齐。

## 五、功能完善清单（已实施）

1. **自动出题升级**（`genQuiz`）：
   - 干扰项优先取自**同科目**其它知识点事实（提升区分度），不足再跨科目补足；
   - 题型从单一“下列属于…内容的是？”扩展为「属于 / 正确的是 / 错误的是」三种模板，两套题随机交替。
2. **纯阅读模式**：无题知识点先读正文 → 主动确认掌握，保留学习闭环且不白送积分。
3. **数据完整性**：导出/导入覆盖全部 22 个状态字段，备份零损失。
4. **常量治理**：新增 `PERIOD_MAX`，移除死代码 `PER_TASK`，统一月假配额引用。
5. **本地化运行**：新增零依赖本地服务器 `server.js`、一键启动 `启动-本地服务.bat`、README 使用指南。

## 七、遗留建议（未实施，供后续迭代）

1. **手写题库扩充**：当前 16.4% 的手写覆盖率偏低，建议优先为 75 个“单句正文”知识点补充手写题（它们连自动出题都无法生成）。
2. **正文打磨**：将 75 个“单句正文”知识点扩写为多句结构（含分号句），可使自动出题覆盖率达到 100%。
3. **数据导出加密**：如需更安全的备份，可加口令加密后导出（当前为明文 JSON，仅本地保存）。
4. **自动化 UI 测试**：目前仅纯函数测试，建议引入 Playwright 等做页面级冒烟测试。
5. **PWA 更新策略**：`sw.js` 已采用 `max-age=0` 回源校验；若长期离线使用，可考虑配置“更新提示”而非静默更新。
