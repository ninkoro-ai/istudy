# AI 能力集成评估与实现说明

> 目标约束：**0 成本、本地化、不引入服务器**。本文评估「讲题」从“复制提示词”升级为“内嵌对话”的可行路径与已落地实现。

## 已落地（v2.2）

1. **BYO API Key（自带密钥）**：在「我的 → AI 设置」填写 API Base URL / 模型 / Key，保存到本机 localStorage。AI 讲题弹窗出现「直接开讲」按钮，请求由浏览器直接发往 API 服务商（OpenAI 兼容接口 `/chat/completions`），**不经任何中转服务器**，依旧零后端成本。
2. **可保存提示词脚本**：每次生成的学科定制提示词可「存为脚本」（命名、复用、删除，最多 20 条），方便反复调用。
3. **保留原路径**：未配置 Key 时，「复制提示词」粘贴到 ChatGPT / 豆包等仍可用，互不影响。

## 路径对比

| 方案 | 成本 | 隐私 | 用户体验 | 风险 | 结论 |
|---|---|---|---|---|---|
| A. 复制提示词到外部 AI（原状） | 0 | 高（内容由用户自行粘贴） | 多一步复制/粘贴 | 无 | 保留为默认 |
| B. BYO API Key 浏览器直连（已实现） | 按用量付费（用户自己的 Key） | 中（Key 存本机、请求直连服务商） | 一键开讲 | Key 存 localStorage，设备被侵入时可被读取 | 已实现，附隐私提示 |
| C. 本地大模型（WebLLM 等 WASM） | 0 | 最高（全离线） | 慢、模型小、手机难跑 | 体积大、质量低 | 二期评估（桌面端可试） |
| D. Cloudflare Worker 代理 | 0（免费额度） | 中（需自建鉴权） | 好 | 需要账号体系与密钥管理，破坏“零后端” | 不建议 |

## 安全与隐私说明

- API Key 仅保存在**本机浏览器 localStorage**，不随数据备份导出（`snapshotS` 不含 AI 配置）；
- 「直接开讲」请求携带 Key 直连服务商，**无中间代理**；建议使用只读/低配额 Key；
- 若设备多人共用，建议使用「复制提示词」方式而非保存 Key；
- 清空数据（btnClear）会一并清除本机 AI 配置。

## 二期候选

1. 对话上下文记忆：把“讲题会话”做成可续接的多轮记录（存 IndexedDB）；
2. 支持自定义模型列表（DeepSeek / GLM / Kimi 等 OpenAI 兼容端点）；
3. 桌面端 WebLLM 本地模型选项（完全离线）。
