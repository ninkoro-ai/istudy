# 多设备同步路径评估（零成本方案）

> 目标：在不引入服务器/付费服务的前提下，让「我ai学习」的数据可以在多台设备间迁移/同步。

## 方案对比

| 方案 | 成本 | 自动化程度 | 隐私 | 适合场景 | 结论 |
|---|---|---|---|---|---|
| A. JSON 手动导出/导入（现状） | 0 | 手动 | 高（不离开设备） | 换机低频 | ✅ 已实现，保底方案 |
| B. 加密备份 + 同步盘（OneDrive/坚果云/微信文件传输） | 0（用户已有网盘） | 半自动 | 高（AES-256 加密后上传） | 日常多设备 | ✅ 已实现加密，推荐日常使用 |
| C. WebDAV（坚果云/Nextcloud） | 0 | 自动（定时/手动一键推送） | 高（可加密后上传） | 有 WebDAV 账号的用户 | ⏳ 二期可做：浏览器 fetch 直传 WebDAV（PUT/GET），免后端 |
| D. File System Access API（保存到本地同步文件夹） | 0 | 半自动 | 高 | Chrome/Edge 桌面端 | ⏳ 可加：`showSaveFilePicker` 保存加密备份到同步文件夹 |
| E. 自建后端（Cloudflare Worker + KV/D1） | 0（免费额度） | 全自动 | 中（需要鉴权） | 想彻底免手动 | ⏳ 需要账号体系与鉴权设计，超出“零后端”约束 |

## 推荐路线

1. **现在（已落地）**：明文/加密导出导入 + IndexedDB 镜像防丢。
2. **短期**：加密备份保存到用户已有的网盘同步文件夹（手动一次即可跨设备）。
3. **中期（二期候选）**：WebDAV 一键同步（坚果云免费账号即可），全部数据 AES 加密后上传，浏览器直连 WebDAV，零服务器成本。
4. **远期（可选）**：Cloudflare Workers 免费额度做加密中转同步（仍需用户自持口令，服务端不可读）。

## 安全性说明

- 无论哪种同步路径，建议使用**加密备份**后再上传：服务端/网盘方只看到密文。
- 口令不出设备（由浏览器本地 PBKDF2 派生密钥），可保证“换设备可恢复、平台不可读”。
